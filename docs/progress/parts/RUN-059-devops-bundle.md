## Currency format found (reported, pattern not loosened)

`tests/api/test_trips.py::test_traveller_counts_and_currency_are_checked` posted `adults=0, children=21` with `currency "gb"` and expected all three fields in one 422. With the pattern on `Money`, a malformed code now fails at request parsing, before the trip domain rules (`trips/domain.py`) run. The 422 then lists only `budget.currency`, with Pydantic's message "String should match pattern '^[A-Z]{3}$'" instead of the domain's "Currency must be a three-letter ISO 4217 code". Any other type error already behaves this way.
The test is split, so each rule is still checked: bad counts with a valid currency give `["adults", "children"]`, and `"gb"` alone gives `["budget.currency"]`. The only other non-conforming fixture, `tests/unit/ai/test_schemas.py` (`currency="inr"`), expects a refusal and still passes. No response uses another format.
