## What ships

- Accounts, profile and dashboard with drafts (sign-in through Supabase Auth).
- A trip form with preferences, budget and must-visit places, and place browsing.
- AI generation from a shortlist of stored places, with validation, repair and a labelled rule-based fallback.
- An editable itinerary: each edit recalculates and revalidates in one transaction. Costs, budget alerts, versions with restore, map with a list, and a printable summary.
- Retrieval-augmented generation: AI-written notes show their sources (Amendment A1).
- The curated demo destination Ahmedabad.
- Any-city mode, behind the switch `any_city_mode` (Amendment A2): city search, live places from OpenStreetMap, guide text from Wikivoyage and Wikipedia, with labels and attribution.

The full list with its records is in the [final report](../final-report.md), sections 2 and 11.

## Known limitations

- **Gemini availability.** While Gemini answers "unavailable", plans are rule-based and labelled. Recorded: 22 of 45 attempts of the final v2 run ended `provider_unavailable` ([final-baseline.md](../../eval/reports/final-baseline.md)), and 1 of 24 attempts on the live dataset was usable ([live-v1-gemini-2026-11-25.md](../../eval/reports/live-v1-gemini-2026-11-25.md)).
- **Live cities** have no prices and no opening hours, little step-free information, and are not checked by the team ([readiness audit](../test-reports/any-city-readiness.md), section 5).
- **Public map and guide services** can be slow or refuse a request; an import then fails with a message and can be tried again.
- **Open gaps** of any-city mode and their owners: readiness audit, section 7. Some are closed by the part records of RUN-096.
- **Known defects:** [defects.md](../test-reports/defects.md).
- **Not measured:** the performance and usability targets listed in the final report, section 7.
- **Account deletion** is an operator procedure ([deployment-guide.md](../guides/deployment-guide.md) §9).
- Staging results on the release candidate: pending (Kirtan). Device, screen-reader and usability sessions: pending (Junaid, Krrish).

## Deploy and upgrade

From [deployment.md](../guides/deployment.md) §6:

- Production is deployed by hand with `deploy-production.yml` from a release tag on `main`, and waits for approval in the GitHub environment `production`. It needs the production templates of IMP-801.
- The release task runs before any service changes: auth stub if missing, migrations, seed, RAG index. A failing release task stops the deploy and the running version keeps serving. An embedding outage only warns (IMD-112).
- The release task runs with the service's current environment, so a new template value reaches it one deploy later.

## Rollback

From [deployment.md](../guides/deployment.md) §6 and §10:

- Run `deploy-production.yml` with the previous tag. Migrations are forward only: a rollback never reverses one, so the older image must work with the newer schema.
- Any-city mode alone: remove `!any_city_mode` from the features variable and deploy. The routes answer 404, the city search disappears, curated trips are unchanged and no data is deleted.
